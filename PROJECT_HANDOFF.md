## 3. Контактная форма и внешние сервисы

### 3.1. Formspree

Endpoint:

`https://formspree.io/f/xyeyobeq`

Форма использует обычные `action` + `method="POST"` как fallback и AJAX через `fetch` при наличии JavaScript.

Локали:

| Страница | `data-locale` | Скрытое поле `language` | Тема |
| --- | --- | --- | --- |
| `index.html`, `en.html` | `en` | `EN` | `Consultation request — {name}` |
| `ru.html` | `ru` | `RU` | `Запрос на консультацию — {name}` |
| `ua.html` | `uk` | `UA` | `Запит на консультацію — {name}` |

Поведение формы:

- обязательные поля: имя, email, запрос;
- максимальная длина email: 254 символа;
- максимальная длина запроса: 1000 символов;
- textarea нельзя растягивать вручную, длинный текст прокручивается внутри;
- ошибки обязательности и формата локализованы;
- email должен иметь полный синтаксис, включая домен и TLD;
- затем браузер запрашивает MX-записи домена через Google Public DNS (`https://dns.google/resolve?...&type=MX`);
- это позволяет принимать как известные публичные, так и реальные корпоративные домены без жёсткого списка разрешённых окончаний;
- во время отправки вся страница блокируется полноэкранным overlay;
- spinner и анимированные точки показываются минимум 3 секунды;
- при успехе круг превращается в зелёную галочку, сообщение остаётся примерно 2,8 секунды, затем overlay закрывается;
- при ошибке показывается локализованный текст с резервным email `Ann.Nutrivibe@gmail.com`.

Ограничение: MX-проверка подтверждает домен, но не существование конкретного ящика. Полная проверка требует email verification flow или серверной проверки.

Не использовать `git add .` автоматически, если в папке появились посторонние файлы. Перед commit всегда проверять `git diff` и `git status`.

## 7. Запуск и редактирование на новом компьютере

### 7.1. Клонирование

Важно клонировать или сразу переключить именно `Version-a`, потому что default branch репозитория всё ещё `main`.

```powershell
git clone --branch Version-a https://github.com/TarasFomenko/AnnaBorodinaWebSite.git AnnaBorodinaWebSite-A

git status -sb
git log -1 --oneline
```

Ожидаемый результат:

- ветка: `Version-a`;
- upstream: `origin/Version-a`;
- HEAD: `a2eff98` или более новый осознанный коммит;
- рабочее дерево чистое.

Если репозиторий уже клонирован с `main`:

```powershell
git fetch origin

```

### 7.2. Опциональные резервные worktrees

На новом компьютере нет необходимости держать три копии. Если нужны отдельные папки:

```powershell
git fetch origin

git worktree add --track -b main ..\AnnaBorodinaWebSite-main origin/main
```

Если локальные ветки уже созданы, использовать `git worktree add <путь> <ветка>` без `-b`.

### 7.3. Локальный просмотр

Для простого просмотра можно открыть `index.html` в браузере. Для более корректного поведения fetch, clipboard и URL лучше запустить любой статический HTTP-сервер.

Например, если установлен Python:

```powershell

```

Открыть:

- `http://localhost:8000/` — EN по умолчанию;
- `http://localhost:8000/en.html` — EN alias;
- `http://localhost:8000/ru.html` — RU;
- `http://localhost:8000/ua.html` — UA.

Подойдёт также Live Server в редакторе. Сборку выполнять не требуется.

### 7.4. Правила редактирования

- Общие UI-изменения делать в `style.css` и `script.js`, затем проверять все языки.
- Английский контент синхронно менять в `index.html` и `en.html`.
